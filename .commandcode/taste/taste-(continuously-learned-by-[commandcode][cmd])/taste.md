# Taste (Continuously Learned by [CommandCode][cmd])
- Prefers portfolio content to reflect actual, real data (e.g., exact skill list, real project screenshots, accurate social links, domain, and copy) rather than placeholder or demo data (e.g., emoji placeholders, `#` links, guessed domains). Confidence: 0.8
- Prefers projects to support multiple category tags (e.g., a single project appearing under both "Machine Learning" and "Hackathon") rather than being restricted to one category. Confidence: 0.6
- Prefers to surface competitive-programming/coding profiles (e.g., LeetCode, CodeChef) in the "Connect With Me"/contact section alongside professional social links (LinkedIn, GitHub, email). Confidence: 0.55
- Prefers all social-link locations across the site (hero, contact, footer) to be kept consistent with the same set of correct handles/URLs, and proactively asks to sync any spot that has drifted out of date. Confidence: 0.7
- Prefers site data (stat counts, dates/years, labels, spelling) to be internally consistent and correct across files/sections rather than drifting — e.g., aligning DSA/problem counts, achievement counters, and year references, and fixing typos before publishing. Confidence: 0.7
- Prefers precise location guidance when asked where to make a change — exact file paths and (where helpful) line numbers rather than a high-level description. Confidence: 0.6
- Prefers the assistant to verify changes build/compile successfully after applying edits (e.g., running `npm run build`) rather than leaving edits unverified. Confidence: 0.55
- Prefers features/integrations to be production-ready — explicitly handling loading, success, and failure states (and bot/spam protection) rather than a minimal happy-path implementation. Confidence: 0.65
- Prefers the assistant to explicitly disclose the assumptions it made when fixing or changing things, rather than proceeding silently on unstated assumptions (asks "tell me what all did you assume"). Confidence: 0.75
- Prefers to delegate work at a high level (e.g., "do the necessary changes") and expects the assistant to proactively identify and apply all required changes rather than requiring step-by-step instruction. Confidence: 0.5
- Prefers to avoid building or maintaining a separate backend — for things like contact forms, uses a frontend/third-party no-backend service (e.g., EmailJS, Web3Forms) that delivers submissions directly to email instead of a self-hosted API. Confidence: 0.9
- Prefers the assistant to clearly flag any manual steps or additions required on their side (e.g., setting env variables, host configuration, restarting a dev server) rather than assuming they will infer them from the code change. Confidence: 0.55
